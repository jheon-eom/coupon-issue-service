# V3 PLAN - Redis 원자 연산 기반 선착순 쿠폰 발급

## 1) 목표
- v2에서 확보한 정합성(500개 초과 발급 방지)을 유지
- DB 비관적 락 병목을 제거해 처리량/응답지연 개선
- 실패 요청의 DB 부하를 줄여 고트래픽 대응력 향상

## 2) 핵심 전략
- 발급 성공/실패 판정을 Redis 원자 연산으로 처리
- 성공 건만 DB(IssueCoupon)에 저장
- 실패 건은 즉시 반환하고 DB write 생략

## 3) API 설계 (v3)
- `POST /api/v3/coupons`
  - 쿠폰 생성
  - Redis 발급 카운터 키 초기화
- `POST /api/v3/coupons/issue`
  - Redis 원자 증가 결과로 발급 가능 여부 판단
  - 가능하면 DB 저장 후 성공 반환
  - 불가능하면 즉시 실패 반환

## 4) 데이터/키 설계
- Redis Key: `coupon:{couponId}:issued`
- 발급 한도: 500 (기존 정책 유지)
- 알고리즘:
  1. Redis 카운터 원자 증가
  2. 증가값 <= 500 이면 성공
  3. 증가값 > 500 이면 실패

## 5) 구현 변경사항
- 의존성
  - `spring-boot-starter-data-redis` 추가
- 설정
  - `application.yaml`에 Redis 연결 설정 추가
  - `docker-compose.yml`에 Redis 서비스 추가
- 코드
  - `v3/controller` 추가
  - `v3/service` 추가
  - Redis 연동 컴포넌트(카운터/원자 연산) 추가
  - 기존 v1/v2는 유지(비교 실험 가능 상태 보존)

## 6) 실패/예외 정책
- Redis 미연결/명령 실패 시 v3 발급은 실패 반환 (DB 폴백 없음)
- DB 저장 실패 시 오류로 처리하고 모니터링 대상에 포함

## 7) 검증 시나리오
- 기능
  - 500건까지 성공, 501건부터 실패
- 동시성
  - 고동시 요청에서도 성공 건수 500 초과 없음
- 성능
  - v2 대비 평균/중앙/상위 퍼센타일 응답시간 개선 여부 확인
  - dropped iterations 및 실패율 패턴 비교
- 회귀
  - v1/v2 엔드포인트 정상 동작 유지

## 8) 완료 기준
- 정합성: 성공 건수 정확히 500
- 성능: v2 대비 처리지연/병목 지표 개선
- 안정성: Redis 오류 시 예측 가능한 실패 동작 확인
