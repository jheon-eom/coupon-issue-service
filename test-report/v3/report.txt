** v3 테스트 목적 **
- v2에서 확보한 정합성(선착순 500개 제한)을 유지하면서 처리 성능(지연/실패율/처리량)을 개선하는 것이 목표
- v3에서는 발급 핫패스를 DB 락 중심 처리에서 Redis 원자 연산 기반으로 변경

** 결론: v3는 v2 대비 성능이 명확하게 개선됨 **
- 처리율은 크게 상승했고, 실패율/지연/드롭 모두 큰 폭으로 감소
- 특히 tail latency(p90/p95) 개선폭이 커서 고부하 구간 안정성이 눈에 띄게 향상됨

** 성능 개선 원인 상세 분석 **
1. DB 비관적 락 직렬화 병목 제거
- v2는 쿠폰 row에 대한 `PESSIMISTIC_WRITE`로 요청이 순차 대기하면서 대기열이 길어짐
- v3는 발급 판정을 Redis 원자 증가 연산으로 처리하여 DB 락 대기 구간을 제거
- 그 결과 요청당 대기 시간이 크게 줄어 avg/median/p90/p95가 모두 개선됨

2. 실패 요청의 DB 경로 단축
- v2는 고동시 상황에서 실패 요청도 DB 경합 영향을 크게 받음
- v3는 발급 불가 요청을 Redis에서 빠르게 판정하고 즉시 반환해 DB write/트랜잭션 부담을 줄임
- DB 커넥션 고갈/타임아웃 압력이 낮아져 `http_req_failed`와 `dropped_iterations`가 동반 감소

3. 핫패스 경량화에 따른 처리량 증가
- Redis 단일 원자 연산은 DB 트랜잭션 대비 비용이 낮고 응답이 빠름
- 동일 시간 동안 처리 가능한 요청 수가 늘어 `http_reqs/s`가 701 -> 1706으로 상승

4. tail latency 개선의 구조적 이유
- v2의 긴 꼬리 지연은 락 대기 + 트랜잭션 대기로 누적되는 형태
- v3는 긴 대기 체인이 짧아져 p95가 28.63s -> 2.74s로 급감
- 사용자 체감 품질 관점에서 v3가 훨씬 안정적인 응답 분포를 가짐

** 해석 시 유의사항 **
- 본 비교는 v2와 v3가 동일/동등한 부하 시나리오 조건이라는 전제에서 유효
- 시나리오 설정(VU, stage, duration)이 다르면 절대 비교값은 왜곡될 수 있으므로, 동일 스크립트 기준 재검증이 가장 정확함
