** v4 테스트 목적 **
- v3의 선착순 정합성(500개 제한) 모델을 유지하면서, 발급 API 핫패스 성능(처리량/지연/실패율)을 추가 개선
- v4에서는 발급 이벤트 전달 계층을 비동기 메시지 큐(Kafka) 기반으로 전환해, 요청-응답 경로에서 DB 저장 부담을 더 낮추는 것을 목표로 함

** 결론: v4는 v3 대비 성능이 전반적으로 더 좋아짐 **
- 처리량 증가, 실패율 감소, 평균/꼬리 지연 감소, dropped iterations 감소가 동시에 관측됨
- 특히 고부하에서 병목 신호였던 dropped_iterations가 크게 줄어 안정성이 개선된 것으로 해석 가능

** v4가 더 좋아진 원인 분석 **
1. 요청 경로에서 DB 저장 분리
- v3는 발급 성공 요청마다 DB insert 트랜잭션을 동기 처리
- v4는 이벤트 발행 후 응답하는 비동기 구조로 변경되어 요청 경로의 DB write 대기가 감소
- 결과적으로 avg/median/p90/p95가 함께 낮아짐

2. 경합 지점의 비동기 흡수
- v3는 동시 성공 요청이 DB 커넥션/트랜잭션 자원을 직접 소비
- v4는 워커가 배치(청크) 단위로 DB를 처리하여 순간 트래픽 스파이크를 큐가 흡수
- 그 효과로 실패율과 dropped_iterations가 감소

3. 빠른 실패/재시도 분리
- DB 저장 실패 처리를 요청 스레드가 아닌 워커 재시도 경로로 분리
- API 계층의 blocking 구간이 줄어 처리율 개선에 기여

** 해석 시 유의사항 **
- v4는 비동기 저장 구조이므로, 본 지표는 "API 응답 성능" 개선을 직접적으로 반영함
- "응답 후 실제 DB 반영 완료까지의 지연"은 별도 소비자 지표(consumer lag, 실패 토픽, 재시도 횟수)로 추가 관측 필요
- v3/v4 비교의 엄밀성은 동일 부하 스크립트/동일 인프라 조건일 때 가장 높음
